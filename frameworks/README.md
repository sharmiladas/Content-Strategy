# Frameworks

## Content-program audit

Use this sequence when several teams create content for the same product or customer journey:

1. Choose one bounded customer task or journey.
2. Gather the source material and planned deliverables that influence it.
3. Record audience, owner, version, channel, lifecycle state, and available performance signals.
4. Mark duplication, contradictions, gaps, stale material, and reuse candidates.
5. Assign ownership to the underlying information, not only the final document.
6. Agree on review, reuse, and measurement before production begins.
7. Revisit the sources after launch and retire what is no longer current.

The companion [content-audit template](../templates/content-audit-template.md) turns these steps into a working table.

## System diagnostic for weak AI answers

When an AI answer fails, check the layers in order:

1. **Source** — Was current, approved information available?
2. **Retrieval** — Did the system select the right source and version?
3. **Context** — Did the relevant evidence reach the model intact?
4. **Generation** — Was the task and its constraint clear?
5. **Evaluation** — Did the test identify the actual failure?
6. **Review** — Did the workflow involve the right decision owner?

See the full essay: [When an AI Answer Misses, Check the Whole System](https://sharmiladas.github.io/articles/broken-layer.html).
